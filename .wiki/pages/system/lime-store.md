# 职责

`lime-store` 用 SQLite 保存媒体库、播放进度、分析缓存、章节、字幕与练习数据；schema 版本常量为 4 [[cite:crates/lime-store/src/lib.rs:L1-L13]]，版本值集中定义 [[cite:crates/lime-store/src/lib.rs:L38-L40]]。

# 公开接口

`Store::open(path)` 与 `Store::open_in_memory()` 是唯一入口，二者在返回前都会执行 `migrate()` [[cite:crates/lime-store/src/lib.rs:L43-L55]]。其余能力以 `Store` 的方法暴露：媒体 upsert/list、章节读写、句子与词替换、分析缓存、进度保存、统计、练习 CRUD、章节拆分与合并等。

# 内部机制

## 连接与迁移

迁移前设置 `journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout=5000` 与 `foreign_keys=ON`；WAL 加 NORMAL 在保证崩溃一致性的同时省掉每次提交的 fsync [[cite:crates/lime-store/src/lib.rs:L57-L66]]。

主表包括 `setting`、`media`、`analysis`、`chapter`、`sentence`、`word`、`progress`、`listen_stat`、`vocab` 与 `exercise`，其中字幕表带有 `(media_id,start_ms)` 与 `sentence_id` 索引 [[cite:crates/lime-store/src/lib.rs:L67-L119]]。迁移语句全部使用 `CREATE TABLE IF NOT EXISTS`，schema 版本写入 `setting` 表而不是 `PRAGMA user_version` [[cite:crates/lime-store/src/lib.rs:L123-L131]]；旧库缺少 `seq` 列时通过列探测补列并回填 [[cite:crates/lime-store/src/lib.rs:L140-L157]]。

## 媒体与章节

媒体 upsert 以 UNIQUE `path` 为冲突键并返回 `media_id` [[cite:crates/lime-store/src/lib.rs:L175-L199]]；批量版本把所有行包进一个 `unchecked_transaction`，避免逐文件 fsync [[cite:crates/lime-store/src/lib.rs:L201-L236]]。`list_media` 通过章节行数推导 `is_analyzed`、通过 `SUM(listen_stat.plays)` 推导播放次数，并按加入时间倒序 [[cite:crates/lime-store/src/lib.rs:L261-L298]]。

写入章节前先 `normalize_chapters`；`overwrite` 删除全部行，`replace` 只删除 `locked=0` 的行，随后按 `(level,parent,ordinal)` 重新认领锁定行并令 `seq = 下标` [[cite:crates/lime-store/src/lib.rs:L309-L333]]。锁定行认领逻辑集中在同文件 [[cite:crates/lime-store/src/lib.rs:L352-L369]]。读取时按 `(seq IS NULL), seq, id` 排序，只要存在空 `seq` 就整体回退到 rowid 排序，再把存储为“下标 + 1”的 `parent_id` 映射回真实下标并重新规范化 [[cite:crates/lime-store/src/lib.rs:L410-L475]]。

## 字幕与缓存

句子与词按媒体整体替换，整个过程在一个事务内完成 [[cite:crates/lime-store/src/lib.rs:L477-L520]]；`clear_sentences` 只删除字幕缓存而保留章节 [[cite:crates/lime-store/src/lib.rs:L528-L539]]。

分析缓存每个媒体一行，同时以 `params_hash`（转写管线指纹）与 `version = SCHEMA_VERSION` 作为有效性条件；查询返回 `Option<(model, params_hash)>` [[cite:crates/lime-store/src/lib.rs:L697-L716]]，写入逻辑在同文件 [[cite:crates/lime-store/src/lib.rs:L718-L736]]。

## 进度

`save_progress` upsert `(pos_ms, updated_at)`，并把章节序号写入名为 `chapter_id` 的列 [[cite:crates/lime-store/src/lib.rs:L750-L760]]；读取进度时对应解析 [[cite:crates/lime-store/src/lib.rs:L762-L777]]。正常 DB 访问在 UI 线程同步执行，只有进度写入被排队到名为 `lime-progress` 的后台线程；该线程打开自己的 `Store` 并从 `mpsc` 队列取任务 [[cite:crates/lime-store/src/lib.rs:L878-L912]]。`Drop` 时先丢弃发送端再 join，保证队列中的写入落盘 [[cite:crates/lime-store/src/lib.rs:L914-L929]]。

# 配置与已知边界

- 本 crate 没有 FTS5 或任何 `MATCH` 查询，只有普通 B-tree 索引；全文搜索不能引用这里 [[cite:crates/lime-store/src/lib.rs:L67-L119]]。
- `has_analysis` 统计的是章节行数而不是 `analysis` 表，因此可能出现“已分析但没有指纹”的状态 [[cite:crates/lime-store/src/lib.rs:L738-L748]]。
- 章节级编辑接口按 `seq` 定位而不是 `ordinal`，因为 `ordinal` 会在不同材料间重复 [[cite:crates/lime-store/src/lib.rs:L779-L796]]。
- `vocab` 表已创建但当前没有读写方法 [[cite:crates/lime-store/src/lib.rs:L105-L108]]。
- 练习选项以 JSON 存储，解析失败时会静默退化为空向量 [[cite:crates/lime-store/src/lib.rs:L599-L695]]。
