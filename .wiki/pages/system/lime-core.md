# 职责

`lime-core` 定义跨 crate 共享的领域模型、错误类型与 `.limed` 文件格式，不包含业务编排逻辑 [[cite:crates/lime-core/src/lib.rs:L1-L26]]。

# 公开接口

错误类型是字符串化的 `Error` 枚举，变体为 `Io/Decode/Asr/Store/Limed`，并提供 `Result<T>` 别名 [[cite:crates/lime-core/src/lib.rs:L5-L19]]。根模块还平铺重导出 `ExerciseQuestion`、`MaterialExercise`、`ExerciseParser`、`find_accompanying_audio`、`find_matching_limed`、`LimedFile` 与 `LimedMeta` [[cite:crates/lime-core/src/lib.rs:L21-L26]]。

# 领域模型

`Media` 描述音频元数据；`ChapterLevel` 只有 `Material` 与 `Question` 两级，题目必须挂在某个材料下 [[cite:crates/lime-core/src/lib.rs:L28-L44]]。`Chapter` 携带 `seq`、`parent: Option<usize>`、1 基 `ordinal`、置信度与 `locked`，其中 `seq` 在旧数据中缺省为 0 [[cite:crates/lime-core/src/lib.rs:L54-L77]]。

章节不变量是：`parent` 是章节向量中的列表下标，`seq` 必须等于该下标，材料排在前面，题目只能挂在当前材料之下；`chapters_are_canonical` 负责校验，首个材料约定标题为“引言” [[cite:crates/lime-core/src/lib.rs:L89-L113]]。

`normalize_chapters` 重建规范顺序且幂等；题目父级解析依次尝试显式 `parent` 且时间重叠、中点包含、区间重叠、最近的前置材料 [[cite:crates/lime-core/src/lib.rs:L115-L137]]。父级匹配的完整实现集中在此 [[cite:crates/lime-core/src/lib.rs:L214-L257]]。

字幕模型由 `Word{start_ms,end_ms,text}`、`Sentence{...,words,chapter:Option<usize>}` 与 `VocabEntry` 组成，其中 `chapter` 是 0 基章节下标 [[cite:crates/lime-core/src/lib.rs:L306-L332]]。

练习模型为 `ExerciseQuestion{num,stem,options,answer?,explanation?}` 与 `MaterialExercise{material_ordinal,title,questions}`；可选字段在序列化时省略，`title` 有默认值 [[cite:crates/lime-core/src/exercise.rs:L3-L18]]，练习容器结构在同文件 [[cite:crates/lime-core/src/exercise.rs:L42-L52]]。

# 练习解析

`ExerciseParser::parse(input, known_material_count)` 优先按 JSON 解析：先尝试非空 `Vec<MaterialExercise>`，再尝试非空 `Vec<ExerciseQuestion>` 并自动分组，最后才回退到文本/Markdown 启发式 [[cite:crates/lime-core/src/exercise_parser.rs:L9-L32]]。

文本词法器用正则识别材料头（`Text|Passage|Section|Conversation|材料|第X节|听力材料`）、题干（`第?N.`、`、`、`)`、`:` 等）、答案（`答案/Key/Answer: A-G`）、解析与答案块结束标记 [[cite:crates/lime-core/src/exercise_parser.rs:L38-L59]]。

解析前先扫描尾部“【参考答案】/Keys”块，把答案收进 `HashMap<u32,String>`；行内答案优先于块答案，主循环遇到答案块标记即结束正文解析 [[cite:crates/lime-core/src/exercise_parser.rs:L61-L82]]。结束条件在同文件 [[cite:crates/lime-core/src/exercise_parser.rs:L126-L128]]。

材料切分要求行匹配材料头、不是题干且字节长度不超过 30；分组按出现顺序编号为 1..n，当只存在一个未命名分组且 `known_material_count > 1` 时会重新分配 [[cite:crates/lime-core/src/exercise_parser.rs:L130-L153]]。单组重分配逻辑在同文件 [[cite:crates/lime-core/src/exercise_parser.rs:L239-L249]]。

选项只在题干打开后提取，要求 A–G 标签出现在行首 4 字节以内，并统一为 `"A. text"`；一行多个选项会被拆分 [[cite:crates/lime-core/src/exercise_parser.rs:L289-L322]]。

# `.limed` 格式

`.limed` 是二进制容器：前 8 字节为魔数 `LIMED`、主版本 `0x01`、压缩算法 `0x01`(zstd)/`0x00`(raw) 与保留字节，之后是 zstd 压缩的 UTF-8 JSON [[cite:crates/lime-core/src/limed.rs:L1-L19]]。文件结构包含 `meta`、`chapters`、`sentences` 与可选的 `exercises` [[cite:crates/lime-core/src/limed.rs:L51-L58]]。

`LimedMeta` 记录音频文件名、时长、采样率、声道数，以及默认化的 `file_size`、`created_at`、`version`、`generator` 和 `asr_fp`；空 `asr_fp` 表示旧缓存或外部工具生成 [[cite:crates/lime-core/src/limed.rs:L21-L49]]。

编码使用 `serde_json::to_vec` 后 `zstd::encode_all(...,3)`；解码拒绝过短文件、错误魔数、版本不等于 1 与未知压缩算法，同时兼容 `COMPRESSION_NONE` [[cite:crates/lime-core/src/limed.rs:L75-L128]]。

兼容性检查允许 ±1500 ms 的时长漂移；若时长差小于 300 ms 则忽略文件大小差异。`find_matching_limed` 依次探测 `<stem>.limed` 与 `<name>.<ext>.limed`，跳过无法解码的文件并直接返回已解码结果 [[cite:crates/lime-core/src/limed.rs:L146-L165]]，探测顺序的完整实现 [[cite:crates/lime-core/src/limed.rs:L172-L198]]。

# 已知边界

- JSON 输入必须是数组；单个对象或 `{"materials":...}` 包装会落入文本解析 [[cite:crates/lime-core/src/exercise_parser.rs:L19-L28]]。
- 材料标题的 30 字节限制按字节计数，超过约 10 个汉字的标题会被误判为正文 [[cite:crates/lime-core/src/exercise_parser.rs:L132-L132]]。
- 单独的“答案/Keys”行会终止正文解析，后续题目被静默丢弃 [[cite:crates/lime-core/src/exercise_parser.rs:L126-L128]]。
- `LimedMeta.version` 与文件头版本是两个独立字段，前者当前未被校验 [[cite:crates/lime-core/src/limed.rs:L27-L32]]。
