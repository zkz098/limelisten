# 职责

`lime-audio` 负责从音频文件到扬声器的整条实时链路：symphonia 解码、signalsmith-stretch 变速、块队列缓冲、cpal 输出，并在帧级实现 seek、循环与变速 [[cite:crates/lime-audio/src/lib.rs:L1-L3]]。

# 公开接口

crate 暴露 `decode/engine/render/resample/stretch` 五个模块，并重新导出 `Engine`、`Shared`、`render`、`write_wav` 与 `RenderOptions` [[cite:crates/lime-audio/src/lib.rs:L8-L15]]。`probe()` 只读取采样率、声道数与时长而不整段解码；读取失败时回退为 44100 Hz、双声道、0 ms [[cite:crates/lime-audio/src/lib.rs:L25-L27]]，默认值定义在同文件 [[cite:crates/lime-audio/src/lib.rs:L54-L69]]。

`Engine` 的传输控制都是非阻塞的薄封装：`play`、`pause`、`seek`、`set_speed`、`set_loop`、`stop_at` 等方法把命令写入有界通道 [[cite:crates/lime-audio/src/engine.rs:L185-L211]]。命令枚举固定为 `Play/Pause/Seek/SetSpeed/Loop/StopAt/Quit` [[cite:crates/lime-audio/src/engine.rs:L89-L97]]。

# 内部机制

## 解码

`Decoder` 封装 symphonia 的 `FormatReader` 与 `AudioDecoder`，记录 `track_id`、采样率、声道数和可复用的样本缓冲 [[cite:crates/lime-audio/src/decode.rs:L14-L21]]。`next_packet` 把所有编码统一转换为交错 f32；遇到 EOF（包括 `UnexpectedEof`）返回 `Ok(None)`，无法解码的包则跳过 [[cite:crates/lime-audio/src/decode.rs:L70-L94]]。`seek_ms` 使用 `SeekMode::Accurate` 与 `SeekTo::Time` 并重置解码器，MP3 的定位粒度约为 26 ms（一帧）[[cite:crates/lime-audio/src/decode.rs:L96-L109]]。

## 输出与队列

输出配置优先沿用文件采样率并请求 F32 设备格式；设备不支持时回退到设备默认配置并启用重采样 [[cite:crates/lime-audio/src/engine.rs:L127-L135]]。cpal 回调按设备默认采样格式分派 F32/I16/U16，构造对应类型的流 [[cite:crates/lime-audio/src/engine.rs:L240-L253]]。队列容量为 60 个块，约 1.3 秒 @48 kHz [[cite:crates/lime-audio/src/engine.rs:L23-L24]]。

`Shared` 用原子量承载可听位置、播放状态、速度、代际/确认、产出与消费帧数、已喂入源帧、循环区间、欠载计数与 EOF 等状态 [[cite:crates/lime-audio/src/engine.rs:L26-L57]]。seek、暂停与循环通过递增 `gen` 让回调丢弃并回收已排队块，并写回 `ack_gen`；工作线程等待确认后才继续生产，因此控制立即生效而不是等待约 200 ms 的队列排空 [[cite:crates/lime-audio/src/engine.rs:L284-L296]]。

暂停会记住可听位置并递增代际；恢复播放时从该位置重新 seek，EOF 后则回到 0 [[cite:crates/lime-audio/src/engine.rs:L413-L429]]。暂停状态下 seek 直接更新 `pos_ms` [[cite:crates/lime-audio/src/engine.rs:L430-L441]]。

## 位置时钟、循环与自动暂停

可听位置不是解码进度，而是“已喂入源帧减去尚未被消费的输出帧换算回的源时间” [[cite:crates/lime-audio/src/engine.rs:L587-L598]]。A-B 循环与自动暂停点在每个块之后基于 `pos_ms` 判定：循环递减剩余次数、seek 回 A 并递增代际；`StopAt` 会钳位位置、置位 `reached_stop`、清空暂停点并暂停 [[cite:crates/lime-audio/src/engine.rs:L600-L626]]。

## 变速与重采样

变速器固定 transpose 为 1.0，只改变时长；速度被钳制在 0.25–4.0，1.0x 时完全绕过 stretcher [[cite:crates/lime-audio/src/stretch.rs:L37-L44]]。启动时丢弃 `output_latency + 2×BLOCK_FRAMES` 的预热样本，避免瞬态被听到 [[cite:crates/lime-audio/src/stretch.rs:L115-L124]]。重采样只是源采样率与设备采样率不一致时的线性插值兜底 [[cite:crates/lime-audio/src/resample.rs:L1-L20]]。

## 离线渲染

`render` 镜像实时链路：seek → 声道规整 → 可选重采样 → 变速 → 跳过预热 → 冲刷尾部 [[cite:crates/lime-audio/src/render.rs:L13-L34]]。`RenderOptions` 默认 1.0x、48000 Hz、双声道、整段、从 0 开始 [[cite:crates/lime-audio/src/render.rs:L37-L68]]，WAV 以流式 16-bit PCM 写出 [[cite:crates/lime-audio/src/render.rs:L136-L166]]。

# 配置与生命周期

`Engine` 持有 cpal 流与音频工作线程；缓冲区通过 `QUEUE_BLOCKS + 4` 的回收通道复用，回调侧使用非阻塞 `try_send`，`Drop` 时发送 `Quit` 结束线程 [[cite:crates/lime-audio/src/engine.rs:L143-L171]]。错误面只使用 `lime_core::Error::Io` 与 `Error::Decode`，不向上暴露底层库类型 [[cite:crates/lime-audio/src/engine.rs:L120-L125]]。

# 已知陷阱

- 回调拿到的是交错样本，但位置按帧计数；计算 `out_consumed` 时必须除以设备声道数，否则会出现约 0.38x 的假速度 [[cite:crates/lime-audio/src/engine.rs:L274-L277]]。
- `SetSpeed` 保存调用方传入的未钳制速度，而钳制发生在 stretcher 内部；从旁路切到变速时还可能暴露启动瞬态 [[cite:crates/lime-audio/src/engine.rs:L442-L445]]。
- `Engine::new_at` 只钳制起始位置，真正出声仍需显式调用 `play()` [[cite:crates/lime-audio/src/engine.rs:L137-L142]]。
